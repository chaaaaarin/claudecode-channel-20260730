7ステップの実践チェックリスト形式。Slackで一言依頼するとAIが動いて結果が返る仕組みを、自分のチームの業務で再現するための設計テンプレート（型②集約・型③量産の実装に使えます）。

■ ステップ1：連携の土台を作る
□ Slackワークスペースの管理者権限があるか
→ YES: Claude Codeの公式Slack連携（Slack App）をワークスペースに追加する
→ NO: 管理者に依頼してから進める

□ 任せたい業務用の専用チャンネルを作ったか（例: #レポート自動化、#SNS企画）
→ YES: そのチャンネルにClaude Codeアプリを招待する
→ NO: 先にチャンネルを作成する
指示例: 「#日次レポート というチャンネルを作って、そこにClaude Codeを招待して」（Slack管理者向け操作。Claude Codeへの指示ではない）

■ ステップ2：任せる業務を1つに絞る
□ 「繰り返し発生する」「毎回やることが決まっている」業務を1つ選べているか
→ YES: その業務の入力（何を渡すか）と出力（何が欲しいか）を書き出す
→ NO: まず業務を書き出すところから始める（数値照合・企画立案・チェック作業などが向いている）
指示例: 「毎朝行っている◯◯業務について、入力として何を確認し、最終的に何を出力しているかを整理して」

→ YES: 次のステップへ
→ NO: 下記の雛形を埋める
指示例:
## ◯◯業務の自動化ルール
- 対象: <毎朝／毎週などの頻度と対象範囲>

- チェックする基準: <具体的な判定基準を箇条書きで>
- 出力先: <Notionのページ／Slackの通知先チャンネル>

→ YES: 依頼文をチームで共有し、誰でも同じ結果が出るようにする
→ NO: 下記の指示例をベースに自分の業務用に書き換える
指示例: 「◯◯業務を実行して。対象は<期間・範囲>、結果は<出力先>にまとめて。何か判断に迷う点があれば先に確認して」

→ YES: 同じ型で2〜3回繰り返し、安定して同じ品質が出るか確認する
→ NO: CLAUDE.mdのルール・出力フォーマットの指定を見直して再度試す
指示例: 「さっきの出力について、◯◯の部分が期待と違ったので、次回からは<修正内容>のようにして」

# チェックするルール

1. 明確なNG（これに該当したら必ず指摘）
【絶対に避けるべき項目を箇条書きで】
（例・広告：断定的な効果表現／経理：規定の上限額超過／人事：選考基準にできない属性への言及
　　　開発：規約で禁止された書き方／法務：責任範囲が無限定な条項）

2. 表記・形式のルール
【社名・製品名・数値・日付などの正しい書き方】
（例：正式名称の指定、大文字小文字、全角半角、日付の表記形式、必須の添付書類）

3. トーン・ニュアンスのルール
【避けたい言い回し、望ましい書き方】

4. 業界・法令に関する注意点
【この分野で特に気をつけるべき規制やガイドライン。該当しない場合は「特になし」と書く】

# チェックの仕方
- 対象を1項目（または1文）ずつ確認し、上記いずれかのルールに該当する箇所を指摘してください
- 該当箇所は原文をそのまま引用し、どのルールに違反しているかを明記してください
- 判定は「問題なし／要確認／明確な違反」の3段階にしてください
- 断定できないものは必ず「要確認」に寄せ、勝手に問題なしと判断しないでください
- ルールに書かれていない事柄については「ルールに記載なし」として別枠で報告してください
- 問題がなければ「チェック完了、指摘事項なし」と回答してください
